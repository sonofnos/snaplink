Snaplink

snap·l1nk = short links, fast

URL shortener.

Built for the redirect path. Links are served from memory, then Redis, then Postgres, so the busiest ones never touch the database.

how it works

A redirect walks down three caches and stops at the first one that has the link. Targets never change, so nothing needs invalidating.

inside

    
    
      
  • layered cachein-process LRU, then Redis, then Postgres. Expiry travels with the cached value.
    • 
      
  • durable idseach instance reserves 1,000 ids at a time from a Postgres sequence. A cache can evict a counter; a sequence can't.
    • 
      
  • async analyticsclicks are queued and written in batches. A slow database drops analytics, never redirects.
    • 
      
  • guarded writeslink creation and sign-in are rate limited through Redis. Redirects never are.
    • 
      
  • accountsserver-side sessions, bcrypt, custom aliases, expiry, per-link analytics.
