01 / The redirect path

Most requests never leave the process.

A redirect walks down a cache hierarchy and stops at the first hit. Link targets never change, so there is nothing to invalidate, only to warm.

02 / What it does

Built like a system, not a demo.

Layered caching

In-process LRU, then Redis, then Postgres. Expiry travels with the cached value, so an expired link can't outlive its time in any layer.

Durable ID blocks

Each instance reserves 1,000 IDs at once from a Postgres sequence. Sequences can't be evicted like a cache key, so codes never repeat.

Async click analytics

Clicks are queued and written in batches. A slow database drops analytics, never redirects.

Guarded writes

Link creation and sign-in are rate limited through Redis. The redirect path is never throttled.
